# 别再伺候 AI 了：5 个方法把 Codex 真正用成助手

很多人开始用 `Codex` 以后，表面上像是在提效，实际却还是自己在复制资料、补背景、反复解释需求。问题不一定在 prompt，而在于你还没把那些重复解释、重复搬运、重复检查的动作交给它自己跑。

![标题封面图](../../assets/posts/cases/stop-babysitting-ai-codex/cover.png)

## 1. 插件：先让 Codex 长出手脚

没有插件的 Codex，更多只是会回答你。接上 Gmail、Google Drive、GitHub、Slack、Figma、Notion 这些插件以后，它才开始能进工具里替你干活。

真正的价值不是“多装了一个插件”，而是你不再需要充当信息中转站。

![插件接入图](../../assets/posts/cases/stop-babysitting-ai-codex/02-plugins-goal.png)

## 2. Goal Mode：不要一句一句微操

普通模式是你说一步，它走一步。Goal Mode 则是你给终点、范围和成功标准，让它自己拆步骤、执行、检查、修正。

如果你想让 Codex 真正承担任务，而不是只承担动作，就得从“发零碎指令”切到“定目标”。

## 3. 自动化：真正的效率是你不叫它，它也会来

最值得自动化的，不是“帮我赚钱”这种虚任务，而是每天、每周都在重复、又容易复查的小流程。

比如整理日志、汇总更新、做状态摘要。自动化的价值，是把“我要记得去做”变成“系统自然会做”。

![自动化与定时工作图](../../assets/posts/cases/stop-babysitting-ai-codex/03-automation-obsidian.png)

## 4. MCP + Obsidian：让它看到你的上下文

互联网给 Codex 外部信息，Obsidian 给 Codex 你的个人上下文。

一旦通过 MCP 打通知识库，它就不再只是根据这一次聊天回答问题，而是能结合你的笔记、素材、项目背景和长期关注主题来输出。

## 5. Skills：把重复说过三遍的话沉淀下来

如果一个流程已经重复讲了三次，就该做成 Skill。

插件解决“去哪里拿资料”，Goal Mode 解决“给它什么终点”，自动化解决“什么时候执行”，MCP 解决“它能看到什么”，Skills 解决“它以后按什么方式做这件事”。

![Skills沉淀图](../../assets/posts/cases/stop-babysitting-ai-codex/04-skills-workflow.png)

## 最后

别追求一次配齐全部能力。先挑一个最痛的重复动作，把它跑通。只要一个最小闭环打穿，你就会明显感觉到：Codex 不再只是回答你，而是在替你分担流程。
