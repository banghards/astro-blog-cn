# Hermes + xurl 不只是发推工具：真正好用的是把它做成一套内容工作流

`xurl` 是 Hermes 里的一个执行型技能，可以让 Agent 直接和 X 交互：搜索帖子、读取讨论、发布内容。

但单独使用 `xurl` 很容易不稳定：流程不一致、没有记忆、缺少质量控制、容易重复话题。它真正有价值的用法，是和 `/goal`、research、multi-step reasoning、memory、planning 组合起来，形成一个可重复运行的内容系统。

最关键的组合是 `xurl + /goal`。`xurl` 负责执行，`/goal` 负责流程结构。一个可靠流程应该包括 research、analysis、drafting、evaluation、publishing 和 memory，而不是直接让 Agent 搜索后发帖。

research 负责把 X 上的讨论变成可用材料；multi-step reasoning 负责避免第一稿直接发布；memory 负责检查过去 7 天或 30 天是否已经发过类似主题和角度。

一个可复用的每日内容工作流可以拆成 6 步：数据收集、风格检查、重复检查、初稿生成、质量评估、发布决策。只有当 hook、洞察、相关性、风格一致性和互动潜力达到阈值时，才进入发布环节。

最常见的错误是：把所有事塞进一个巨大 goal、评估标准太松、没有记忆追踪、太早全自动。更稳的方式是先手动跑 5 到 7 天，确认输出稳定，再设置早晚定时运行。

`xurl` 的价值不只是“能发内容”，而是可以作为整个 Hermes 内容系统里的最后执行环节。真正值得搭建的是一套从研究、写作、评估、发布到记忆沉淀的闭环。
