# 跑了几个月 Hermes Agent 之后，我发现 99% 的人根本没用对 AI Agent

现在很多人都在说 AI Agent。

但如果你认真观察大多数人的使用方式，会发现一个很尴尬的现实：

他们嘴上在用 Agent，手上其实还是在用聊天机器人。

问一句。

回一句。

再补一句背景。

再追一句“继续”。

整个过程看起来像在让 AI 干活，实际上还是人类一直在牵着走。

这也是为什么很多人用了一阵子 Agent 以后，会觉得“好像也没想象中那么强”。

问题不一定在模型，也不一定在产品。

更大的问题是：

**绝大多数人，从来没有真正把 Agent 当成一个会持续上班、会逐步学会你工作方式的系统来用。**

连续跑了几个月 `Hermes Agent` 以后，我反而越来越确定一件事：

Hermes 最恐怖的地方，不是它能执行任务。

而是它会慢慢记住你是谁、你做过什么、你怎么工作，并把这些经验沉淀成可复用的技能和记忆。

这才是它和普通聊天 AI 最本质的差距。

## 1. 大多数人用错 Agent 的地方，不在技术，而在心态

很多人一说 Agent，就会想到：

- 会不会自动点按钮
- 会不会自己跑任务
- 会不会自己写代码
- 会不会自己上网查资料

这些当然重要。

但它们只是表层能力。

真正决定一个 Agent 值不值得长期用的，其实是三个更底层的问题：

第一，它会不会记住你的上下文。

第二，它做完一轮事情以后，会不会变得更懂你。

第三，它下次再遇到同类任务时，能不能直接沿用上次沉淀下来的方法。

如果这三点做不到，那所谓 Agent 很容易退化成“会执行任务的聊天框”。

你每次都还得重新解释。

重新补背景。

重新告诉它格式、偏好、标准、优先级。

这根本不是真正的代理系统。

这只是把人类的重复劳动，换了一种更像“对话”的形式而已。

而 Hermes 真正吸引人的地方，在于它从设计上就在解决这个问题。

---

## 2. Hermes 的核心，不是自动化，而是“越用越懂你”

普通聊天 AI 更像是：

每次和你重新认识一次。

你不说，它就不知道。

你不补背景，它就只能泛化回答。

你这次说过的话，下次大概率还得再说一遍。

Hermes 更像另一种东西。

它不是只在当前对话里“临时理解你”。

而是在持续运行中，一点点积累你是谁、你在做什么、你偏好什么、哪些方式对你有效。

这里最关键的一点是：这些记忆不是黑箱。

不是你看不见的云端数据库。

它以本地 Markdown 文件的形式存在。

你可以打开、修改、删除。

这件事的意义非常大。

因为它意味着，你不是在使用一个随时可能忘掉一切的临时助手。

你是在训练一个会逐步长出“你的工作习惯”的数字员工。

而且更重要的是，Hermes 不是只存历史。

它还会把做过的任务经验写回自己的技能库。

也就是说，它不是“记住你说过什么”这么简单。

它是在把工作经验转成可以复用的方法。

这才是 Agent 该有的样子。

![记忆与技能沉淀图](./illustrations/02-memory-skills.png)

## 3. 不要拿 Hermes 去替代 Codex，它们根本不是一个工种

很多人最容易犯的另一个错误，是喜欢问：

Hermes 和 Claude Code 谁更强？

和 Codex 谁更强？

和 OpenClaw 谁更强？

这种问法本身就有问题。

因为它默认大家在竞争同一个岗位。

但实际并不是。

如果一定要用一个最直观的比喻：

Hermes 更像是 `Chief of Staff`。

它擅长的是：

- 持续跟进任务
- 长期保留记忆
- 做研究、文档、运营、内容整理
- 通过 cron 和消息平台主动推进事情

而 `Claude Code` / `Codex` 更像是深度编程搭子。

它们在写代码、改架构、做复杂测试、推进大型工程任务时更强。

所以更成熟的用法不是拿它们硬碰硬。

而是清楚地分工：

- 日常任务、研究、内容、文档、电脑管理，用 Hermes
- 深度写代码、大型项目、复杂调试和测试，用 Codex 或 Claude Code

这不是谁取代谁。

而是谁在什么位置最合适。

真正高效的人，最后都会走到这种分工思路上。

![Hermes与Codex分工图](./illustrations/03-agent-division.png)

## 4. Hermes 真正像员工的地方，是它会在你睡觉时继续干活

很多产品都能“接受任务”。

但能不能像一个真实员工一样，在你不盯着的时候继续推进，才是分水岭。

Hermes 最像员工的地方，不是 `/goal` 这个命令本身，而是它和定时任务、消息平台、长期记忆结合在一起以后形成的工作方式。

你可以给它一个持续目标。

你可以通过 Telegram 远程指挥它。

你可以让它在固定时间跑 cron。

你还可以让它把经验写回记忆和技能系统。

这意味着什么？

意味着你不是在临时“召唤”一个回答器。

而是在持续驱动一个会主动推进事情的系统。

比如你完全可以让它：

- 每天凌晨自动做一个小工具或小页面
- 固定时间整理某个研究方向的新信息
- 定时生成报告、摘要、文档草稿
- 持续跟踪某个项目状态并回传

白天你给方向。

夜里它继续推进。

第二天你看到的，不是一句“我建议你做什么”。

而是一个已经开始往前跑的结果。

这时候它才真正像 Agent，而不是聊天机器人。

---

## 5. 第一天别急着让它干活，先让它认识你

很多人装好 Hermes 以后，第一反应是赶紧给它派一个任务。

这很正常。

但其实更正确的顺序，是先做“入职 onboarding”。

你不会让一个新员工第一分钟就开始盲干。

你总得先告诉他：

- 你是谁
- 你做什么
- 你最重要的目标是什么
- 你当前在推进哪些项目
- 你的工作偏好和输出要求是什么

Hermes 也一样。

如果你一上来什么都不说，只让它开始做事，那它能做的只能是泛化执行。

而如果你第一天就认真把这些基础信息喂进去，它之后的主动任务、判断优先级、选择输出方式，都会更贴着你的真实工作目标。

这个步骤看起来朴素，但特别关键。

很多人说 Agent 不够聪明。

其实常常不是 Agent 不够聪明，而是你根本没有认真给它建立工作上下文。

---

## 6. 真正值得学的不是命令，而是 Agent 工作流

Hermes 当然有命令。

比如 `/goal`、状态查看、暂停、恢复、清理当前目标、追加子目标这些。

这些都重要。

但如果只记命令，很容易又回到“功能清单式使用”。

真正应该学的是它背后的工作流：

先告诉它你是谁和你正在做什么。

再给它长期目标，而不是零碎动作。

再通过 Telegram 这类平台保持低成本远程协作。

再用 cron 让它主动跑起来。

再让它把经验沉淀回技能和记忆。

这样才会形成一个会不断强化自己的闭环。

这也是为什么很多人装了 Agent 以后，最后只觉得“挺新鲜”，但没有形成生产力。

因为他们用到的只是功能。

没有真正把 Agent 放进工作流里。

![24小时主动工作流图](./illustrations/04-24x7-workflow.png)

## 最后：99% 的人不是没用 Agent，而是没真正让 Agent 上班

说到底，大多数人没用对 AI Agent，并不是因为他们没装、没测、没折腾模型。

而是因为他们始终把 Agent 当作“等待自己提问的对象”。

而不是一个：

- 会持续保留上下文
- 会记住你的工作方式
- 会沉淀经验
- 会在你不盯着的时候继续推进任务

的长期系统。

Hermes 之所以让人觉得不一样，就在于它更接近后者。

它不是只是更会回答。

而是更像一个能逐步长出“工作记忆”和“工作方法”的 AI 员工。

这也是为什么，真正跑了一段时间以后，你最明显的感受通常不是“它更聪明了”。

而是：

**它越来越像你的助理了。**

这才是 Agent 和聊天机器人的真正分水岭。
